## High-Performance Patch-Match Multi-View Stereo: Separating Algorithmic Cost from Implementation Overhead

Highly accurate, complete, and fast 3D multi-view stereo (MVS) reconstruction has remained a topic of great interest in recent years. Galliani et al. introduced Gipuma in 2015, demonstrating that PatchMatch stereo can be massively parallelized on GPUs through the checkerboard propagation scheme. Since then, the patch-match family has become the dominant paradigm for non-learning-based dense reconstruction. A rich succession of algorithms has built upon this foundation: ACMH/ACMM introduced adaptive checkerboard sampling, multi-hypothesis joint view selection, and multi-scale geometric consistency; ACMP and ACMMP added triangulation-based planar priors; APD-MVS introduced adaptive patch deformation; HPM-MVS proposed non-local extensible sampling and hierarchical prior mining; and most recently DVP-MVS, MSP-MVS, DPE-MVS, and DVP-MVS++ have incorporated more priors, including ones produced by deep monocular estimation networks embedded into the traditional pipeline. Each successive method improves benchmark quality, yet each also inherits and compounds the runtime and memory cost of its predecessors. Published runtime comparisons on the ETH3D benchmark show that state-of-the-art methods can require several times the runtime and memory of the earlier ACM-family methods for quality gains of a few percentage points. The literature treats this cost as an unavoidable consequence of algorithmic sophistication, mitigated only through downsampling, "fast" variants, or by declaring the runtime "acceptable".

This thesis challenges that assumption. Its central claim is that a significant portion of the observed performance degradation is not intrinsic to the algorithms but is an artifact of research-grade software practice: successive methods are routinely implemented as forks of their predecessors' codebases, inheriting data structures, memory access patterns, and kernel designs that were never revisited with performance in mind. Because publications compete on benchmarking accuracy rather than efficiency, systematic performance engineering — profiling, memory layout optimization, occupancy tuning, kernel fusion, host-device transfer minimization — is largely absent from this line of work.

The thesis will first provide a comprehensive review and taxonomy of the patch-match MVS family, tracing the lineage of both the algorithms and their reference implementations, and characterizing the constraints each method introduces along with its reported quality gains and performance costs. It will then profile representative reference implementations to decompose their runtime into three distinct sources: inherent algorithmic complexity, implementation overhead, and external pipeline dependencies such as embedded deep learning-based depth map preprocessing. Finally, it will demonstrate through a production-grade reimplementation of a selected method that a substantial fraction of the lost performance can be recovered without sacrificing reconstruction quality, thereby making otherwise impractical methods feasible for real-world use and providing the 3D reconstruction community with both high-quality open software and evidence-based implementation guidelines. For evaluations, the open-source ETH3D high-resolution multi-view benchmark will be used;

The work is structured around the following research questions:
- To what extent is the performance decline across successive patch-match MVS algorithms attributable to genuine algorithmic complexity versus inherited implementation inefficiency?
- Which implementation-level factors (memory access patterns, GPU occupancy, redundant computation, data layout, host-device transfers) contribute most to the performance gap in existing reference implementations?
- Can a systematically engineered, production-grade reimplementation of a recent state-of-the-art method recover a substantial fraction of the runtime and memory cost while preserving its benchmark accuracy?
- What software engineering and performance optimization practices should the MVS research community adopt to prevent the continued accumulation of avoidable overhead in future methods?

**Keywords:** \[Multi-view stereo, Computer Vision, 3D reconstruction, PatchMatch, Performance Engineering, GPGPU\]
